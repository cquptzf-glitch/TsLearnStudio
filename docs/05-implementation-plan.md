# TsLearnStudio 开发实施计划、验收与质量门禁

- 版本：v0.1
- 范围：先完成需求/架构/UI 基线，再实现可运行单课 MVP，随后建设完整课程与前后端项目环境
- 分支约束：默认在 main 上进行小步提交；不主动创建新开发分支

## 1. 总体实施策略

采用垂直切片，而非先开发一堆没有业务内容的 UI 组件。每阶段产生一个可运行的学习闭环，并有自动化回归测试。

规划流程：
1. 设计基线：需求、技术架构、课程及 UI 原型。
2. Spike：安全 IPC、Monaco、编辑器存储、运行器取消/超时、内容 Schema。
3. P0 MVP：第一课从学习到提交、自动评测、恢复进度。
4. 基础课程：加入 Web/JS/TS 课程和特定可视化组件。
5. P1 项目环境：React/Node 多文件工程、API、预览和测试。
6. 完整内容：48 课产出/审校/回归。
7. 发布：Windows 安装包与持续集成检查。
8. P2 AI 和扩展：明确独立于离线基本能力。

## 2. 阶段任务与 Done 定义

### M0 · 产品设计基线（当前）
交付：README、PRD、技术架构、课程与评测设计、UI 规范、可打开的 UI-only 原型。
验收：文件链接均正确；描述中的「目标能力」与「已实现能力」明确区分；UI 原型能打开、能切页面/切主题；不运行学员代码。

### M1 · Electron 工程骨架
- 初始化 electron-vite + React/TS strict；
- 建立 Main / Preload / Renderer / shared 目录与 eslint/format/typecheck；
- 确认 contextIsolation、sandbox、nodeIntegration 默认配置；
- typed IPC + sender/schema 校验；
- 初始化 UI Shell：导航、主题、首页、设置；
- Vitest + 基础 E2E 工程；
- Windows 开发/打包验证。

Done：全新克隆后依据 README 可启动；主进程/渲染进程无 TS 错误；不在 renderer 暴露 fs、shell、child_process 等能力；一条基础 IPC 测试通过。

### M2 · 单课完整学习闭环（首个真正 MVP）
- Course Manifest + Loader + Schema 校验；
- Markdown 课程渲染、Lesson Step 流程；
- Monaco 与 TypeScript Diagnostics；
- WorkspaceService、自动保存和恢复；
- 可信基础题运行器、超时/停止、console 输出；
- 自动测试、Attempt/Report、错误提示；
- SQLite 进度与历史；
- TS-ASYNC/JS 基础示范课至少一课完整交付。

Done：新用户可连续完成「学习→编辑→类型检查→运行→失败反馈→修复→提交→进度恢复」。覆盖启动失败、超时、语法错误、存储失败及取消。

### M3 · 第一阶段课程与可视化
- WEB/JS/TS 的课程内容逐课交付；
- 动画引擎提供 Play/Pause/Step/Reset 和减少动效；
- 课程列表、搜索、错题、掌握度；
- 完善教程里的 C++/Qt 对比。
Done：每节已标为交付的课均通过课程质量门禁；没有只含标题的“完成课程”。

### M4 · Web/React/Node 项目模式
- HTML/CSS/DOM 安全预览；
- 独立标准 Node 运行时探测或打包方案；
- React/Vite 预览和真实 HMR；
- Node API 任务管理、进程树/端口回收；
- 文件树、多编辑器标签、日志、HTTP 请求工具；
- Vitest 集成、测试报告、项目快照；
- 运行外部 npm 脚本前安全提示与能力约束。
Done：能使用内置模板完成 React + Node + SQLite CRUD，并在关闭软件时清理运行的进程；模拟恶意/异常输入不影响可信 Main。

### M5 · 完整课程与毕业项目
- 完成 48 节课程正文、交互、题目、反例与评测；
- Mini TestPilot M1–M8 的毕业项目任务；
- 课程依赖、错题推荐、阶段报告；
- 每课 1 次内容审查 + 1 次运行验证。
Done：全部课程通过内容门禁；毕业项目可从零启动并评测核心功能。

### M6 · 质量收敛与发行
- Windows x64 打包、全新环境验证；
- CI 全链路 typecheck/lint/unit/integration/E2E；
- 运行器安全评审、错误恢复测试、磁盘写入测试；
- 文件迁移与内容升级、日志脱敏与导出；
- 性能测量、快捷键及无障碍检查。
Done：在预定义支持的 Windows 目标机器上按安装说明可完成 M2 验收流程；发布说明包含已知限制。

### M7 · 可选 AI 辅助
- 配置模型服务、内容选择与隐私提醒；
- 基于当前课程/代码/测试报告解释错误；
- AI 提示不得篡改真实测评结果；
- 无 AI 配置仍可用。
Done：用户能关闭 AI，课程与评测功能无降级；网络断开有明确错误提示。

## 4. 测试矩阵

| 范围 | 必测场景 |
| --- | --- |
| 课程 | 加载、坏 manifest、课时版本迁移、资源缺失 |
| 编辑器 | 大文本、诊断、复制、撤销、草稿恢复、多 Tab |
| 运行器 | 正常、编译错、异常、死循环、超时、强行退出、日志上限 |
| 评测 | 正例、反例、边界、重复提交、工具错误、隐藏测试隔离 |
| IPC | 非法 sender、未知 channel、路径遍历、超长文本、JSON schema 失败 |
| 文件 | 断电模拟写入中断、软链接逃逸、目录不存在、无权限、Windows 路径 |
| 预览 | 不允许导航可信应用、不暴露 preload、CSP、跨源请求 |
| 项目 | 启动失败、端口占用、停止、进程树残留、断网缺依赖 |
| 数据 | 首次初始化、历史迁移、事务回滚、导出/恢复 |
| UI | 明暗主题、缩放、键盘操作、对比度、减少动效 |
| 发布 | 干净 Win11 机器安装/启动/卸载、资源完整、升级兼容 |

## 5. 发布质量门禁

- **功能**：本次声明交付的 FR 必有实际演示与对应测试。
- **静态质量**：TypeScript strict、lint、format、依赖锁版本。
- **行为测试**：单测通过、集成测试通过、关键 UI E2E 通过。
- **安全**：Electron 安全设置、IPC sender/schema 校验、运行器隔离评审。
- **恢复能力**：工作区与进度可持久化；重置/升级不误删用户文件。
- **文档**：功能完成状态、限制、操作说明同步更新。
- **提交**：小步提交说明清楚；不可把未实现能力写入 README 的「已完成」。

## 6. 风险登记册

| 风险 | 概率/影响 | 应对 |
| --- | --- | --- |
| 在 Node 进程里执行恶意代码 | 高/高 | 受信任模板、授权、OS 级隔离研究，禁止声称“沙箱安全” |
| npm 安装脚本造成副作用 | 中/高 | 禁止自动执行外部脚本，用户确认、依赖缓存 |
| 课程数量多但不够深入 | 高/高 | 内容质量门禁；先做精品样板课 |
| Monaco 与 TS 版本不匹配 | 中/中 | 固定版本/集成验证 |
| Dev server 泄露本地接口 | 中/高 | 绑定 loopback、随机端口、token、限制来源 |
| 课程升级破坏进度 | 中/高 | 内容 revision、迁移、备份 |
| Electron 打包很大 | 高/低 | 预估产物、按需下载扩展依赖 |
| 过度设计导致交付拖延 | 高/中 | 单课垂直闭环，P1/P2 明确后置 |
| UI 原型被误认为完整软件 | 中/中 | 原型固定显眼标注，只用于设计 |
