# TsLearnStudio 需求规格说明（PRD / SRS）

- 版本：v0.1（设计基线）
- 状态：待实施，功能状态以验收记录为准
- 平台：Windows 11 x64 优先；macOS/Linux 列为后续评估
- 核心人群：有 C/C++、Qt 或其他语言经验，希望通过 AI 辅助开发、阅读和修改 TS/Web/Node 代码的工程师

## 1. 背景、问题与目标

### 1.1 用户问题
传统课程把讲解、代码编辑、运行、提交与复习分散在网页、IDE、终端和多个文档中；AI 生成的前端/后端代码可以运行，却容易在类型、异步、状态和 API 边界上看不懂或改不对。

### 1.2 北极星目标
在同一个桌面程序内完成：选择学习路径 → 原理讲解 → 互动演示 → 编辑示例 → 运行/调试 → 自动评测 → 复盘 → 综合项目。最终能独立定位 AI 代码的问题并验证修复，而不是仅背诵语法。

### 1.3 可验证的学习结果
- 能读懂 TS 泛型、联合类型、类型收窄、模块、Promise/async 与错误处理。
- 能沿 React 组件、Props、State、Effect 追踪数据与重渲染。
- 能沿浏览器 Network → HTTP 路由 → Node 业务逻辑 → 数据存储追踪完整请求。
- 能在不依赖 AI 提示的情况下完成小范围修改，使用断点、类型检查和测试证实修改正确。
- 能在应用内完成一个小型全栈测试用例管理项目。

### 1.4 成功指标（验收建议值，而非当前事实）
- 初次使用：用户在 5 分钟内开始第一节课并完成首个练习。
- MVP 闭环：一节课从打开到提交、失败提示、重新提交、进度持久化全部可用。
- 练习引擎：内置可重复运行的题目相同代码给出一致结果；错误报告可定位到文件、行、断言。
- 课程覆盖：正式课程发布前，每一课有目标、概念、例子、练习、评测和讲解；不得用空白占位冒充已完成课程。
- 无网络：不依赖云端账户完成阅读、本地练习、进度保存；需要下载的依赖有明确提示。

## 2. 产品原则与范围

1. 学习优先：默认只出现当前步骤需要的工具；编辑器高级面板按需展开。
2. 实践优先：每个核心知识点至少一项可操作的练习。
3. 原理优先：重点可视化事件循环、异步、DOM、React 渲染、HTTP 数据流。
4. 检验优先：对代码运行结果、测试结果和 AI 建议进行独立验证。
5. 本地优先：课程与学习状态本地保存，必要的远程能力均为可选。
6. 安全优先：学员代码不在 Electron 主进程执行；执行权限、文件范围和网络权限均显式约束。
7. 可扩展：课程格式、运行器、评测器、UI 分层，未来可加入其他语言。

### 2.1 MVP（P0）
课程目录/导航、结构化单课、Markdown/交互知识卡、Monaco 单文件编辑、TS 类型诊断、受控 JS 基础题运行、自动断言评测、讲解式错误反馈、本地工作区、进度持久化、恢复/重置练习、主题/字体设置、基础异常提示、运行记录。

### 2.2 二期（P1）
HTML/CSS/DOM 实时预览、React/Vite 多文件项目、Node.js 后端 API、请求调试、多文件工作区、Vitest、项目模板与快照、综合项目、课内时序动画、搜索、错题复习、键盘快捷键。

### 2.3 三期（P2）
可选 AI 教练、知识图谱、个性化补弱、更多动画、课程导入、完整调试集成、跨平台、版本化更新机制。

### 2.4 明确不做（首版）
不承诺在不可信任环境安全执行任意恶意 Node/npm 脚本；不做在线多人协作、云账户同步、在线代码提交判题服务、完整 VS Code 扩展生态、移动端应用、复杂商业付费系统。

## 3. 主要用户场景

- US-01：熟悉 C++ 的开发者阅读 Promise、Event Loop，并对比 Qt Signal/Slot，观察运行顺序。
- US-02：用户修改一段 AI 生成的 fetch 代码并让隐藏测试验证 HTTP 404 与网络异常。
- US-03：用户在一节 React 课程中改变 State，看到预览和组件重新渲染说明。
- US-04：用户完成一个 Node API 练习，查看请求/响应和服务端日志，修复错误状态码。
- US-05：用户中途退出，下次进入继续编辑的作业和阅读位置，且不会无提示覆盖。
- US-06：离线打开课程和基础题，缺失工具链或依赖时给出明确修复路径。
- US-07：用户查看错题，定位概念薄弱点并重做，而非只看到一个总分。

## 6. 用户流程与状态

典型单课状态：未开始 → 学习中 → 可练习 → 运行中 → 评测中 → 待修正/已通过 → 完成。页面退出时保留独立编辑草稿。运行中关闭课时应提示中断进程。重置代码与清除进度是两种不同操作。

完成定义：阅读完成不等于能力掌握；测验、练习与项目验收分别存状态。课程页显示「已读」「练习通过」「已掌握」等独立指标。

## 7. 典型验收脚本

### AT-01 首次学习闭环
新安装 → 不登录 → 打开课程 → 阅读 → 编辑有错误的 TS → 看到诊断 → 修正 → 运行 → 示例断言通过 → 提交 → 记录进度 → 关闭软件重开仍显示完成。

### AT-02 失败与恢复
运行死循环/超时题 → 触发超时 → 可终止 → 重新编辑提交；输入语法错误要显示 TypeScript 错误位置；删掉工作区文件应显示恢复方案而非崩溃。

### AT-03 数据完整性
修改作业但未提交 → 切换页面 → 返回保留草稿；重置必须确认且能恢复初始模板；课程升级后历史尝试仍可读取。

### AT-04 权限
通过 renderer 控制台尝试访问 fs 或发起未知 IPC → 被拒绝；工作区外路径写入/符号链接逃逸被拒绝；预览中的网页不得得到 preload 的高权限 API。

### AT-05 作业判定
相同输入和相同测试配置重复提交得到相同确定性测试结果；正常、边界与失败路径均覆盖；测试配置版本进入记录。

## 8. 核心取舍和待验证问题

- 优先一次只运行一个基础练习，二期引入队列及并发配置。
- MVP 只执行可信内置课程的受限代码路径，不承诺抵御恶意用户主动攻击本机。
- 完整 Node/npm 运行器须在阶段二通过安全评审；对外部项目显示风险提示，不得静默运行包安装脚本。
- Electron 内置 Node 并不自动提供完整 npm 发行版；标准项目运行所需工具链和缓存要在环境自检中明确。
- 真正的课程「完成」只有内容、练习、测试、复盘均齐全后才能标记为已交付。

## 9. 术语
- Lesson：一节课程；Step：课程内部学习步骤；Exercise：练习题；Attempt：一次提交；Runner：代码执行器；Grader：评测器；Workspace：学员编辑文件的工作区；Snapshot：可恢复的文件版本快照。
