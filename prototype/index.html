Promise、事件循环与 async/await

课程讲解概念 / 示例 / C++ 对照

理解异步的执行语义

JavaScript 的异步编程并不等同于“每个异步函数都创建一个线程”。在常见的浏览器主线程场景中，同步代码执行完成后，事件循环调度后续回调与任务。

本节目标
① 区分 Promise 状态与 HTTP 业务结果；② 说明 await 的暂停/恢复行为；③ 解释同步任务、微任务与计时器回调的先后关系。

1. async/await 到底做了什么？

await 让当前异步函数在等待 Promise 结果时暂停后续语句的执行，同时把控制权交还给调用方。它不会阻塞整个 JavaScript 主线程。

console.log("A");
setTimeout(() => console.log("D"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("B");
// 输出：A → B → C → D

2. 和 C++ / Qt 的区别

场景C++ / QtJavaScript / TypeScript
异步模型线程、事件循环、Future 等Promise + 事件循环

错误处理异常、结果码、信号reject、throw、try/catch
AI 代码常见误区
把 await fetch() 的成功完成理解为 HTTP 200。实际上 404/500 通常仍会返回一个 Response，需要检查 response.ok。
运行机制执行顺序

一次异步请求如何结束？

从发起请求到处理结果，需要把“网络层完成”和“应用层判断”拆开。正式版会提供可单步播放的时序动画；这里先给出可读的状态流程。

1
调用 fetch() 并创建 Promise

后续代码由 await 挂起，函数返回 Promise。

2
收到 HTTP 响应

即便状态码为 404，网络请求可能正常完成，Promise fulfilled。

3
检查 response.ok

只有 2xx 通常视为 HTTP 成功；其他状态应按业务规则处理。

4
解析 JSON 并验证数据结构

TypeScript 的类型断言不能替代运行时校验。

5
反馈到 UI

区分加载中、成功、HTTP 错误、网络错误和无效数据。

对比：网络连接失败
网络错误可能导致 fetch Promise rejected；此时进入 catch 分支，与 HTTP 404 不同。

修复 AI 生成的请求函数

右侧 loadUser.ts 直接把 response.json() 作为结果返回。你需要补齐 HTTP 错误判断，并考虑网络失败和非法数据的边界。

验收要求

  • HTTP 200 且 JSON 合法时返回用户对象。
  • HTTP 404/500 不允许当作业务成功。
  • 网络异常和 JSON 解析异常必须可识别。
  • 避免把 as User 误认为运行时数据校验。
