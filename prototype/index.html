INTERACTIVE WORKBENCH

Promise 与 async/await

JS-08 · JavaScript 运行机制 · 实践示例
核心知识

理解异步，不只是记住语法

JavaScript 通常在主线程执行代码。遇到异步操作时，执行控制权会交还给事件循环； Promise 的后续工作通过微任务调度。

C++ / Qt 对比
await 不等于阻塞整个线程；它更接近异步函数的暂停与恢复，和同步等待 Future 的行为不同。

核心判断

fetch 收到 HTTP 404 时，Promise 通常不会因状态码而自动 rejected，因此需要检查 response.ok。

const res = await fetch("/api/users");
if (!res.ok) throw new Error("HTTP " + res.status);
可视化设计

Promise 状态变化

正式产品会支持逐帧播放、暂停、单步、回退和减少动效。当前原型展示流程结构。

发起 fetch→Pending→Response→检查 ok
分支 A：HTTP 404
fetch fulfilled（返回 Response），随后业务代码根据 status / ok 判断失败。
分支 B：网络失败
fetch rejected，可进入 catch；和 HTTP 状态码错误不一样。

课程复盘

这一课应该掌握

① Promise 完成与业务成功是不同概念。
② await 让当前异步函数挂起，而不是锁死整个主线程。
③ 类型断言不是数据校验。
④ 应覆盖成功、HTTP 错误、网络异常与不合法 JSON。
